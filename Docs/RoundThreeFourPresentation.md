# 3·4회차 연출 연결 및 검증

InGame 씬의 InGameCore에 RoundThreePresentation과 RoundFourPresentation을 연결했습니다. CSV의 시간, 활성화 여부, 배정 수는 변경하지 않았습니다. Unity 플레이 검증은 사용자가 진행합니다.

## 현재 데이터와 연출의 차이

- 3회차는 기존 Quest 15의 발생·해결 이벤트를 사용합니다. 현재 데이터 대상은 I_3 베개입니다. 이불 SYNC_04__UNI_02_FoldedBlanket은 연출 위치 기준이며, 새로운 이불 상호작용을 임의로 추가하지 않았습니다.
- 4회차 귀신 접근 연출은 미션과 독립적으로 게임 시각 03:30부터 활성화됩니다. Quest 28 영정사진 미션은 현재 비활성이므로 미션 해결에 따른 영상 엔딩은 아직 발동하지 않습니다.
- 발생 시각은 현재 CSV를 따릅니다. 기획서의 01:30으로 임의 변경하지 않았습니다.

## 3회차

사건 발생 → 이불 옆 스탠딩 여자 귀신 → 사건 해결 즉시 I_15 피 글씨 활성화 → 복도 트리거 진입 → 조명 3회 점멸 및 암전 → 조명 복구와 함께 기어다니는 여자 귀신 돌진 → 돌진 중 화면 점멸과 카메라 흔들림 순서입니다.

스탠딩 귀신은 사건 해결 즉시 사라집니다. 돌진 귀신은 플레이어와 충돌하지 않고 통과하며, 돌진 이동 종료 즉시 사라집니다. 피 글씨는 다음 회차 초기화까지 유지합니다. 조명, 화면, 소리는 돌진 종료 시 복구합니다.

1. Play 후 InGameCore의 GameSessionHost에서 Test Round Id를 3으로 지정하고 컴포넌트 메뉴의 `테스트/지정 회차 시작`을 실행합니다.
2. CCTV 확인과 현장 순찰을 진행하고, 현재 테이블의 Quest 15를 해결합니다.
3. 빠른 연출 확인은 RoundThreePresentation 메뉴의 `테스트/3회차 사건 연출 시작 (미션 상태 유지)`를 실행한 다음 `테스트/3회차 해결 연출 (미션 상태 유지)`를 사용합니다. 실제 미션 상태는 바뀌지 않습니다.
4. 복도 감지 영역에 플레이어로 진입해 점멸·돌진·셰이크를 확인합니다.
5. 다음 회차로 초기화했을 때 귀신과 피 글씨가 사라지고 조명이 원래 밝기로 돌아오는지 확인합니다.

Standing Anchor는 침대 옆 귀신의 발 위치, Corridor Anchor는 복도 감지 영역의 중심, Rush Anchor는 돌진 시작 위치입니다. 씬에 빈 오브젝트를 배치하고 재생 전에 연결하면 됩니다. 기존 Standing Anchor 연결은 유지했습니다.

앵커가 없으면 모델과 피 글씨 위치에서 계산한 임시 배치를 사용합니다. 지정 복도에 정확히 맞추려면 Corridor Anchor 및 Trigger Size를 조절하세요. Lights가 비어 있으면 복도 주변 조명을 초기화 시 한 번 수집합니다. 의도한 조명만 꺼지게 하려면 Lights를 직접 지정하세요. Blink Count, 점멸 시간, Rush Speed, Pass Distance, Shake Strength를 Inspector에서 조정할 수 있습니다.

## 4회차

4회차 03:30 도달 → 화환 근처 남자 귀신 및 접근 감지 활성화 → 접근 영역 진입 시 환경음 Cut 및 심장박동 재생 → 가까운 영역 진입 시 안쪽으로 이동 후 소멸 → 심장박동 Cut 및 환경음 복구 순서입니다. 회차당 한 번 실행되며 미션 발생·해결 여부와 무관합니다. Activation Hour/Minute 기본값은 3/30입니다. 세션 시간 배율과 자정 경계를 반영하고, 시각을 건너뛰어도 다음 갱신에서 활성화됩니다. 시각 도달 시 이미 감지 영역 안에 있다면 플레이어 조작이 가능한 상태에서 발동합니다.

1. GameSessionHost의 테스트 기능으로 4회차를 시작하고 현장 순찰 상태로 전환합니다.
2. 03:30 이전에는 자동 등장하지 않는지, 03:30 도달 또는 이후 시각으로 건너뛰면 등장하는지 확인합니다. 시간 조건을 생략한 배치 테스트에만 `테스트/4회차 귀신 연출 (미션 상태 유지)`를 사용합니다.
3. 먼 접근 영역과 가까운 접근 영역을 순서대로 통과해 소리 전환과 귀신 퇴장을 확인합니다.
4. `테스트/엔딩 미리보기 (클리어 전환 없음)`를 실행하면 임시 엔딩 화면이 2초 표시됩니다. 미리보기는 미션과 클리어 씬을 변경하지 않습니다.

Peek Anchor는 화환 뒤 귀신의 발 위치, Retreat Anchor는 방 안 퇴장 위치입니다. Approach Anchor와 Close Anchor는 각각 먼/가까운 감지 영역 중심입니다. 기본 배치는 I_14 주변 화환을 기준으로 계산하므로, 실제 4빈소 입구에 맞는지는 플레이 검증과 앵커 조정이 필요합니다.

Ambience Sources에는 기존 환경음 AudioSource들을 연결합니다. 배열이 비어 있으면 임시 환경음을 사용합니다. 임시 환경음과 심장박동은 현재 dummy 음원으로 연결되어 있습니다. 실제 음원 확보 후 슬롯만 교체하면 됩니다. 모든 전환은 Cut이며 Crossfade는 적용하지 않았습니다.

## 엔딩과 향후 데이터 연결

Ending Clip이 비어 있으면 임시 종료 화면을 표시합니다. 영상을 지정하면 영상 종료 후 도메인에 완료를 요청하고 기존 GameClear 흐름으로 연결합니다. 영상 준비 실패 시에도 임시 종료 화면으로 대체합니다.

실제 엔딩 미션은 다른 배정 미션까지 모두 해결한 후 완료할 수 있습니다. 엔딩 중에는 게임 시간과 입력을 제한하고, 중복 완료 요청은 한 번만 처리합니다. 미리보기 중에도 시계와 조작을 잠시 제한하고 종료 시 해제합니다.

추후 테이블에서 영정사진 미션을 활성화할 때는 Quest·Schedule·Round의 활성 상태와 배정 수를 함께 맞추고 Target의 실제 I_14 경로를 연결해야 합니다. 이불도 실제 타깃 행과 미션을 연결해야 합니다. Bootstrapper의 추가 허용 경로는 등록된 데이터 행의 연결만 허용하며, 경로가 있다는 이유로 상호작용을 생성하지 않습니다. 미션 ID를 바꾸면 연출 컴포넌트의 Quest Id도 함께 맞추세요.

## 구조와 검증 범위

GameSession은 배정·해결·엔딩 상태를 소유하고, 회차별 MonoBehaviour는 완료 이벤트를 받아 모델·조명·사운드를 제어합니다. 연출은 Update 기반 상태 진행을 사용합니다. 모델과 감지 영역은 초기화 때 생성하여 회차마다 재사용하고, 맵 검색도 초기화 때 수행합니다. 카메라 흔들림은 렌더링 중에만 적용하고 원래 카메라 Transform을 복구합니다.

네트워크 전송은 구현하지 않았습니다. 추후 권한 있는 세션이 미션/엔딩 상태를 결정하고, 각 클라이언트가 결과 이벤트를 받아 연출하는 경계로 확장할 수 있습니다. 연출 시간과 애니메이션은 게임 규칙의 결정론적 시뮬레이션에 포함하지 않습니다.

`Tools/PresentationChecks/Run.ps1`은 NuGet 다운로드나 Unity 실행 없이 설치된 .NET 10으로 엔딩 규칙을 검사합니다. 351개 검증을 통과했습니다. 이는 미션 순서, 엔딩 중 시간 정지, 중복 완료, 비활성 미션 유지에 대한 검사이며 실제 모델 배치·물리 감지·청취·영상 재생을 검증한 결과는 아닙니다.
